# Как выпустить релиз

Релиз собирает и публикует GitHub Actions — workflow `.github/workflows/release.yml`.

> **Главное, что нужно знать:** workflow подписан **только на пуш тега** вида `v*`.
> Мерж в `develop` или `main` не запускает ничего. Нет тега — нет сборки и нет релиза.

```yaml
on:
  push:
    tags:
      - 'v*'
```

## Порядок действий

### 1. Довести изменения до `main`

Рабочий поток: `feature/<номер>` → `develop` → `main`. Мержи идут через pull request на GitHub.
Тег ставится на `main`, когда всё, что должно войти в релиз, уже там.

### 2. Поднять версию

В `app/build.gradle.kts`:

```kotlin
versionCode = 2        // обязан увеличиваться на каждом релизе
versionName = "0.2.0"  // совпадает с тегом без префикса `v`
```

- **`versionCode`** — целое, только вверх. Если его не поднять, Android откажется ставить новый APK поверх установленного: для системы это та же самая версия.
- **`versionName`** — то, что видит пользователь. Держите его равным тегу без `v`, иначе в релизе `v0.3.0` будет лежать APK, который называет себя `0.2.0`.

Бамп версии — обычный коммит, он должен попасть в `main` **до** установки тега.

### 3. Поставить и запушить тег

```bash
git checkout main
git pull
git tag v0.2.0
git push origin v0.2.0
```

Тег обязан указывать на коммит, где версия уже поднята.

### 4. Проверить результат

- Вкладка **Actions** → запуск «Release APK». Сборка идёт несколько минут (`./gradlew assembleRelease` на чистом раннере).
- Вкладка **Releases** → появится релиз с именем тега, автоматическими release notes и файлом `EnglishVoiceTutor-v0.2.0.apk`.

## Что делает workflow

1. Забирает код на теге, ставит JDK 17 и Gradle.
2. Собирает `./gradlew assembleRelease`.
3. Кладёт APK в `dist/EnglishVoiceTutor-<тег>.apk`.
4. Создаёт GitHub Release и прикладывает APK.

Секретов и ключей не требуется: release-сборка подписана debug-ключом (см. `signingConfig` в `app/build.gradle.kts`).

## Подводные камни

- **Тег без бампа версии.** Сборка пройдёт, но APK внутри будет со старым `versionCode`, и пользователи не смогут обновиться. Проверяйте `app/build.gradle.kts` перед тегом.
- **Тег поставлен не на тот коммит.** Workflow собирает ровно то, на что указывает тег, а не «последнее в main». Перенести тег: `git tag -d v0.2.0 && git push origin :refs/tags/v0.2.0`, затем поставить и запушить заново.
- **Подпись debug-ключом.** Ключ на раннере не тот, которым подписаны локальные сборки, и он может смениться. Установка «поверх» тогда не пройдёт — пользователю придётся удалить приложение, а вместе с ним уедут скачанные модели (LLM ~2.6 ГБ, STT ~500 МБ, голос ~75 МБ) и весь прогресс обучения. Для регулярных обновлений нужен постоянный release-keystore в секретах репозитория.
- **Ветка `master` в проекте отсутствует** — основная называется `main`.
- **Размер APK.** Сам APK небольшой: модели в него не входят, они скачиваются на устройство при первом запуске.

## Быстрая шпаргалка

```bash
# 1. изменения уже влиты в main
# 2. бамп версии в app/build.gradle.kts → коммит → в main
git checkout main && git pull
git tag v0.2.0
git push origin v0.2.0
# 3. Actions → Release APK → Releases
```
