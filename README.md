# English Voice Tutor

Android-приложение — голосовой репетитор английского языка. Распознавание речи, языковая модель и синтез речи работают локально на устройстве. Интернет необходим для первоначальной загрузки моделей и других сетевых операций, если они предусмотрены используемыми источниками.

**Основной стек:** Kotlin, Jetpack Compose, MVVM, Hilt, Room.

**Голосовой цикл:** микрофон → STT → LLM → TTS → сохранение диалога в историю.

## Возможности

### Голосовые диалоги

- Распознавание английской речи.
- Генерация ответов локальной языковой моделью.
- Озвучивание ответов синтезированной речью.
- Выбор сценария и уровня английского по CEFR: A1–C2.
- История диалогов и возможность продолжить разговор.
- Завершение разговора по команде прощания.
- Настройка голоса и скорости синтеза речи.

### Учебная программа

- Курс английского языка с уровнями от A1 до C1.
- Тематические уроки с учебными целями, словами и грамматическими правилами.
- Словарь с переводом, транскрипцией и примерами.
- Интервальное повторение слов по системе Лейтнера.
- Грамматические правила с объяснениями на русском языке.
- Разбор диалогов с исправлениями и пояснениями.
- Отслеживание прогресса обучения.

### Локальная обработка

Основные операции распознавания речи, генерации текста и синтеза речи выполняются на устройстве. Это позволяет использовать приложение без постоянного обращения к облачным AI-сервисам после загрузки необходимых моделей.

## Технологии и архитектура

| Компонент | Технология |
|---|---|
| Язык | Kotlin |
| UI | Jetpack Compose |
| Архитектура | MVVM |
| Dependency Injection | Hilt |
| Локальная база данных | Room |
| STT | sherpa-onnx, Parakeet |
| LLM | LiteRT-LM, Gemma |
| TTS | sherpa-onnx, Piper/VITS |
| Учебный контент | JSON в `assets/curriculum/` |

### Голосовой цикл

1. Пользователь запускает запись с микрофона.
2. STT преобразует речь в текст.
3. LLM формирует ответ с учётом контекста разговора и учебного сценария.
4. TTS синтезирует речь.
5. Диалог сохраняется в локальной базе данных.

Интерфейс и `ConversationViewModel` работают через интерфейсы `SttEngine`, `LlmEngine` и `TtsEngine`. Конкретные реализации связываются в `di/AppModule.kt`.

Это позволяет менять движки, не переписывая пользовательский интерфейс и основную логику диалога.

## Установка и запуск

### Готовая сборка

Готовый APK можно найти во вкладке [Releases](https://github.com/OneCOlyl/EnglishVoiceTutor/releases).

1. Скачайте APK последнего релиза.
2. Установите его на Android-устройство.
3. При необходимости разрешите установку приложений из неизвестных источников.
4. При первом запуске настройте и загрузите языковую модель.
5. При первом использовании микрофона приложение загрузит модель распознавания речи.

### Требования к устройству

- Android 8.0 или новее (`minSdk 26`).
- Реальное Android-устройство с микрофоном.
- Для GPU-инференса LLM требуется поддержка OpenCL.
- Ориентир по оперативной памяти — 8 ГБ или больше; фактические требования зависят от модели и устройства.
- Для первоначальной загрузки моделей необходимо подключение к интернету.

Работа на эмуляторах не является целевым сценарием и может быть ограничена особенностями аудиоввода и GPU.

### Запуск из Android Studio

1. Установите Android Studio и необходимые Android SDK.
2. Откройте корневую папку репозитория.
3. Дождитесь синхронизации Gradle.
4. Подключите физическое Android-устройство с включённой отладкой по USB.
5. Выберите конфигурацию приложения и запустите модуль `app`.

Если Gradle Wrapper отсутствует или не настроен, восстановите его в соответствии с конфигурацией проекта.

### Сборка из командной строки

На Linux/macOS:

```bash
./gradlew assembleDebug
```

На Windows:

```powershell
.\gradlew.bat assembleDebug
```

APK обычно находится в:

```text
app/build/outputs/apk/debug/
```

Запуск unit-тестов:

```bash
./gradlew test
```

Запуск проверок Android-модуля:

```bash
./gradlew check
```

Набор доступных задач зависит от конфигурации Gradle. Перед выпуском проверяйте также instrumented-тесты, если они настроены в проекте.

## Модели машинного обучения

### LLM — языковая модель

Используется `LiteRtLlmEngine` на базе LiteRT-LM и семейства Gemma 4.

- Модель загружается через экран первоначальной настройки.
- Для предустановленного источника Gemma может потребоваться токен Hugging Face.
- Альтернативный вариант — указать прямую ссылку на совместимый файл `.litertlm`.
- При отсутствии подходящей модели полноценный голосовой диалог недоступен.

Параметры каталога моделей находятся в `domain/model/LlmModelOption.kt`. Установка и загрузка выполняются через `data/model/ModelInstaller`.

### STT — распознавание речи

Используется `SherpaOnnxSttEngine` с Parakeet unified-en 0.6B (int8).

- Модель загружается при первом использовании микрофона.
- Ориентировочный размер — 500 МБ.
- Загрузка и файлы модели хранятся локально в каталоге приложения.
- Используется push-to-talk: одно нажатие запускает запись, повторное останавливает её.

### TTS — синтез речи

Используется `SherpaOnnxTtsEngine` с Piper/VITS `en_US-libritts_r-medium`.

- Ориентировочный размер модели — 75 МБ.
- Модель загружается при первой необходимости озвучивания.
- Можно выбирать голос и скорость речи.
- Синтез не зависит от системного Android Text-to-Speech.

Озвучивание может начинаться с первого готового предложения, однако генерация ответа LLM в текущей реализации сначала может завершаться целиком.

### Хранение моделей и токенов

Модели хранятся в локальном каталоге приложения. Токен Hugging Face вводится пользователем для источников, которым он необходим; согласно текущей реализации, токен не сохраняется между запусками.

Не публикуйте токены, персональные данные и другие секреты в исходном коде, логах, задачах или коммитах.

## Учебная программа

Учебный контент находится в `app/src/main/assets/curriculum/`.

Файлы организованы по уровням CEFR, например `a1.json` и `c1.json`. Контент включает темы, словарь и грамматические правила.

### Прогресс обучения

Прогресс хранится в Room. Идентификаторы элементов контента используются для связи с сохранёнными результатами.

**Важно:** изменение идентификаторов слов или правил может нарушить связь с ранее сохранённым прогрессом. При изменении структуры контента проверяйте совместимость с существующими данными.

### Интервальное повторение

`SrsSchedule` реализует расписание повторения слов. Учебная сессия формируется через `VocabularyRepository`.

Изменения алгоритма повторения необходимо проверять unit-тестами на известных наборах входных данных.

### Использование LLM в обучении

Учебный контент хранится в приложении и не должен зависеть исключительно от генерации модели. LLM дополняет отдельные сценарии, например формирует дополнительный пример или проверяет употребление слова.

## Известные ограничения

Этот список отражает известные на момент документирования ограничения. Перед изменением кода проверяйте, актуальны ли они в текущей версии.

- Автоматическое определение конца речи по тишине (VAD) не используется в основном сценарии записи.
- Озвучивание не обязательно начинается одновременно с генерацией первого токена LLM: генерация ответа может завершаться до начала TTS.
- Суммаризация длинных диалогов не используется в основном потоке; контекст ограничивается количеством последних сообщений.
- Токен Hugging Face не сохраняется и может потребоваться повторно.
- Загрузка LLM выполняется в контексте `viewModelScope`; при уничтожении соответствующего scope операция может прерваться. Возможность продолжения зависит от механизма загрузки.
- Иконка приложения может требовать отдельной доработки.
- Автоматизированное тестовое покрытие ограничено. В частности, миграции Room и ключевые сценарии диалога нуждаются в проверке.
- Прогресс хранится локально и не синхронизируется с облаком; при удалении данных приложения он может быть потерян.
- Порядок добавления новых слов в повторение может определяться порядком курса, а не фактической историей изучения тем.

При обнаружении новых ограничений добавляйте их в соответствующую спецификацию и создавайте задачи в `TASKS.md`, если требуется дальнейшая работа.

## Specification-Driven Development (SDD)

В проекте используется подход **Specification-Driven Development**: требования и критерии проверки определяются до реализации, а изменения кода проверяются на соответствие спецификациям.

README описывает приложение и его запуск. Спецификации определяют ожидаемое поведение. `TASKS.md` связывает требования с конкретными работами.

### Принципы работы

1. **Сначала исследование.** Перед изменением существующей функциональности изучите текущую реализацию.
2. **Требования до реализации.** Зафиксируйте ожидаемое поведение и граничные случаи.
3. **Проверяемость.** У каждого требования должны быть критерии, позволяющие определить соответствие реализации.
4. **Трассируемость.** Задачи ссылаются на идентификаторы требований.
5. **Минимальные изменения.** Не переписывайте работающий код без подтверждённой причины.
6. **Тестирование.** Проверяйте успешные сценарии, ошибки, отмену операций и сохранность данных.
7. **Актуальность документации.** После изменения поведения обновляйте соответствующие спецификации.

### Рабочий процесс

```text
Исследование проекта
        ↓
Проверка и уточнение требований
        ↓
Планирование и декомпозиция задач
        ↓
Реализация
        ↓
Тестирование и проверка критериев
        ↓
Обновление спецификаций и статусов
```

### Жизненный цикл изменения

1. Найдите относящиеся к изменению требования.
2. Проверьте, как соответствующее поведение реализовано сейчас.
3. Уточните спецификацию, если требования неоднозначны или неполны.
4. Создайте задачу в `TASKS.md` с идентификаторами требований и критериями приёмки.
5. Реализуйте минимальное необходимое изменение.
6. Запустите подходящие тесты и проверки.
7. Проверьте критерии приёмки.
8. Обновите документацию и статус задачи.

Если обнаружено расхождение между спецификацией и текущим приложением, не следует автоматически считать ошибочной реализацию. Сначала определите, какое поведение является ожидаемым, и при необходимости согласуйте изменение спецификации.
