# English Voice Tutor

Android-приложение — голосовой репетитор английского. Работает **офлайн**: распознавание речи, LLM-репетитор и синтез речи крутятся на самом устройстве. Сеть нужна только один раз — чтобы скачать модели при первом запуске.

Архитектура: Kotlin + Jetpack Compose, MVVM, Hilt, Room.

Голосовой цикл: **микрофон → STT (Parakeet 0.6B через sherpa-onnx) → LLM (Gemma 4 через LiteRT-LM) → TTS (Piper через sherpa-onnx) → сохранение в историю**.

## Скачать и установить

Готовый APK — на вкладке [**Releases**](../../releases). Скачайте `.apk` из последнего релиза на Android-устройство и установите (потребуется разрешить установку из неизвестных источников).

Что важно знать перед установкой:

- **Только реальное устройство.** Нужны микрофон и GPU с OpenCL для LLM (ориентир — 8 ГБ ОЗУ). На эмуляторе не заработает.
- **`minSdk 26`** (Android 8.0 и выше).
- При первом запуске приложение **докачает модели** (LLM и STT) — на это нужна сеть один раз. Для LLM Gemma нужен токен HuggingFace; можно также указать свою прямую ссылку на модель `.litertlm` без токена. Подробности — ниже в разделе «Откуда качаются модели».

Выпуск новой версии — см. [RELEASE.md](RELEASE.md) (релиз собирается по пушу тега `v*`, мерж в `main` сам по себе ничего не запускает).

## Статус по компонентам

| Компонент | Реализация | Детали |
|---|---|---|
| STT (распознавание речи) | `SherpaOnnxSttEngine` — Parakeet unified-en 0.6B (int8) через sherpa-onnx | Модель `~500 МБ` скачивается лениво при первом нажатии на микрофон, в `filesDir`. Push-to-talk: тап — старт, ещё тап — стоп. Сама расставляет пунктуацию и регистр. |
| LLM (репетитор) | `LiteRtLlmEngine` — Gemma 4 E2B/E4B через LiteRT-LM, backend GPU с откатом на CPU | Модель `~2.6 ГБ` (E2B) скачивается на экране первого запуска (нужен токен HuggingFace). |
| TTS (синтез речи) | `SherpaOnnxTtsEngine` — Piper/VITS `en_US-libritts_r-medium` через sherpa-onnx | Модель `~75 МБ` скачивается лениво при первой озвучке. Не зависит от наличия системного движка TTS. Озвучивает по предложениям, начиная говорить до конца синтеза. Голос и скорость речи выбираются в «Настройках». |
| История диалогов | Room (`Conversation`/`Message`), экран «История», продолжение разговора | В контекст LLM отдаются последние `20` сообщений (`RECENT_MESSAGES_FOR_CONTEXT`). |
| Сценарий/уровень | Форма при старте диалога: текстовое поле сценария + выбор CEFR (A1–C2) | Системный промпт собирается в `TutorPrompt`. |
| Программа обучения | Roadmap A1 → C1: 28 тем с целью, сценарием, словами и правилами | Контент — статический JSON в `assets/curriculum/`, прогресс — в Room. Экран «Курс». |
| Словарь | 224 слова с переводом, транскрипцией и примером; интервальные повторения | Планировщик — `SrsSchedule` (система Лейтнера). Экраны «Слова» и «Повторение». |
| Грамматика | 55 правил с объяснением по-русски, примерами «как надо / как не надо» и типичной ошибкой | Экран «Правила»; кнопка «Ещё пример» просит LLM дополнить статику. |

> `StubTutorLlmEngine`, `AndroidSttEngine`, `VoskSttEngine` и `AndroidTtsEngine` (системный `TextToSpeech`) ещё лежат в `data/engine/` как альтернативные реализации (заглушка LLM, системный `SpeechRecognizer`, Vosk-STT, системный синтез речи), но **в сборке не используются** — активные движки привязаны в `di/AppModule.kt`.

## Как открыть и запустить

1. Открыть папку проекта в Android Studio (актуальная стабильная версия). При первом открытии Studio предложит сгенерировать Gradle wrapper — согласитесь, либо запустите `gradle wrapper` вручную.
2. **Запускать только на реальном устройстве** — микрофон и GPU-backend LLM на эмуляторе не работают как надо. Нужно устройство с достаточной памятью (ориентир — 8 ГБ ОЗУ и GPU с OpenCL).
3. Требования к устройству: `minSdk 26`. GPU-инференс использует OpenCL (`libOpenCL.so` объявлена как опциональная native-library в манифесте).
4. Первый запуск открывает экран **«Настройка модели»**: выберите источник и скачайте LLM. Для Gemma нужен токен HuggingFace (`hf_...`), т.к. репозиторий gated; вариант **«Своя ссылка»** позволяет скачать любую модель `.litertlm` по прямому URL — без HuggingFace и токена. Дальше приложение стартует сразу в «Историю».
5. При первом нажатии на микрофон докачается STT-модель английского (`~500 МБ`) — это отдельная загрузка, токен не нужен.
6. Сменить модель позже можно на экране **«Настройки»** (иконка шестерёнки в «Диалогах»): выбор из каталога либо своя ссылка. Смена скачивает новый файл и переинициализирует движок.
7. Там же — **выбор голоса озвучки и скорости речи**. Дикторы модели анонимные (номера говорящих из корпуса LibriTTS-R), поэтому вариантов двенадцать и выбираются они на слух: тап сразу применяет голос и проговаривает пробную фразу.

### Откуда качаются модели

- **LLM:** каталог моделей и вариант «своя ссылка» — в `domain/model/LlmModelOption.kt` (`LlmModelCatalog`). Активный файл всегда `model.litertlm` в `filesDir`. Скачивание и подключение к движку — общий `data/model/ModelInstaller` (переиспользуют экраны настройки и настроек); загрузка резюмируемая (докачка через HTTP `Range`, только для той же модели). Токен HuggingFace добавляется в заголовок `Authorization` только для источников с `requiresToken`. Предустановленный вариант: `https://huggingface.co/litert-community/gemma-4-E2B-it-litert-lm`.
- **TTS:** Piper (VITS) `vits-piper-en_US-libritts_r-medium` (~75 МБ, 904 голоса, 22.05 кГц) — архив с релизов `k2-fsa/sherpa-onnx` (тег `tts-models`), качается при первой попытке озвучить что-либо. Голос и скорость хранятся в `VoicePreferences`, список вариантов — `domain/model/VoiceOption.kt` (`VoiceCatalog`), по умолчанию `sid=200` и скорость `0.9×`.
- **STT:** Parakeet unified-en 0.6B (int8, non-streaming) — архив `sherpa-onnx-nemo-parakeet-unified-en-0.6b-int8-non-streaming.tar.bz2` с релизов `k2-fsa/sherpa-onnx`, распаковывается в `filesDir`. URL — в `SherpaOnnxSttEngine`. Каталог модели прошлой версии (Whisper `small.en`) удаляется автоматически при первом запуске после обновления.

Готовность LLM определяется наличием файла `filesDir/model.litertlm` (см. `MainActivity` → `AppNavHost.isModelReady`).

```
app/src/main/

   ├─ EnglishVoiceTutorApp.kt    — @HiltAndroidApp
   ├─ di/AppModule.kt            — привязки движков (Stt/Tts/Llm) и Room. Единственное место смены реализаций.
   ├─ domain/
   │  ├─ TutorPrompt.kt          — сборка системного промпта (главный рычаг качества на маленькой модели)
   │  ├─ SrsSchedule.kt          — интервальные повторения (коробки Лейтнера), чистые функции
   │  └─ model/                  — доменные модели: Conversation, Message, CefrLevel, VoiceUiState,
   │                               ModelDownloadState, Curriculum (темы/слова/правила/прогресс)
   ├─ data/
   │  ├─ engine/                 — Stt/Tts/Llm движки (интерфейсы в Engines.kt)
   │  ├─ model/                  — ModelInstaller (LLM) и ArchiveModelDownloader (общий
   │  │                            загрузчик .tar.bz2 моделей sherpa-onnx для STT и TTS)
   │  ├─ curriculum/             — CurriculumSource: чтение и кеш статического курса из assets
   │  ├─ local/                  — Room: AppDatabase (+миграции), ConversationDao, LearningDao, Entities
   │  └─ repository/             — ConversationRepository, CurriculumRepository, VocabularyRepository
   └─ presentation/
      ├─ setup/                  — экран первого запуска (скачивание LLM)
      ├─ history/                — список диалогов + создание нового
      ├─ conversation/           — экран диалога, голосовой цикл (ConversationViewModel)
      ├─ learning/               — курс, тема, словарь, повторение, правила (экраны + вьюмодели)

      └─ theme/
```

Ключевая развязка: UI и `ConversationViewModel` зависят только от интерфейсов `SttEngine`/`TtsEngine`/`LlmEngine` (`data/engine/Engines.kt`). Смена реализации — это одна строка в `di/AppModule.kt`.

## Программа обучения: как устроен контент

Курс лежит в `assets/curriculum/` — по файлу на уровень CEFR (`a1.json` … `c1.json`). Формат одинаковый: уровень → темы → `vocabulary` и `rules`. Правка курса не требует изменений в коде: `CurriculumSource` читает файлы через `org.json`, собирает доменные модели и кеширует их в памяти.

- **id слова** строится как `<topicId>:<word>`, **id правила** — как `<topicId>:rule<индекс>`. Прогресс в Room ссылается именно на эти id, поэтому переименование слова или перестановка правил внутри темы обнулит прогресс по ним. Добавлять новое в конец списка безопасно.
- **Связь с диалогом.** Кнопка «Говорить по теме» открывает обычный голосовой экран, но сценарий и уровень берутся из темы, а в системный промпт добавляется учебный фокус (`TutorPrompt.TopicFocus`): невыученные слова темы и по одному эталонному предложению из каждого её правила. Грамматику модели объясняем не текстом правила (он на русском), а образцами предложений — маленькая модель надёжнее копирует структуру, чем следует метаописанию.
- **Прогресс темы** считается из двух условий сразу: был хотя бы один диалог по теме и выучено ≥ 80% её слов (`TopicWithProgress.isDone`).
- **Повторения.** `SrsSchedule` — система Лейтнера с интервалами 0/1/3/7/21/60 дней; с 4-й коробки слово считается выученным. Сессию собирает `VocabularyRepository.buildSession()`: сначала просроченные слова, затем до 5 новых, всего не больше 20 карточек.
- **LLM поверх статики.** Модель не является источником контента: она добавляет ещё один пример к правилу (`TutorPrompt.extraExample`) и проверяет фразу, произнесённую со словом (`TutorPrompt.wordUsage`). Без скачанной модели оба раздела работают полностью, теряются только эти две кнопки.

> ⚠️ В KDoc нельзя писать пути вида `assets/curriculum/*.json`: блочные комментарии в Kotlin вложенные, и `/*` внутри комментария молча «съедает» остаток файла.

## Дальнейшие шаги / известные упрощения

- **VAD не задействован.** В `VoskSttEngine` объявлены пороги (`SPEECH_THRESHOLD`, `SILENCE_CHUNKS_TO_STOP`) под авто-детекцию конца фразы, но цикл записи их не использует — сейчас чистый push-to-talk. Довести до авто-остановки по тишине (или Silero VAD) — отдельная задача.
- **TTS озвучивает по предложениям, но не по мере генерации LLM.** `SherpaOnnxTtsEngine` дробит готовый ответ на предложения и начинает говорить с первого, однако сам ответ всё ещё ждёт полной генерации: `LlmEngine.generateReply` отдаёт `Flow<String>`, но вьюмодель собирает его целиком перед озвучкой.
- **Суммаризация длинных диалогов не вызывается.** `LlmEngine.summarize` и `TutorPrompt.summarization` есть, но при очень длинных диалогах контекст просто обрезается по `RECENT_MESSAGES_FOR_CONTEXT` в `ConversationRepository`. Поле `summary` в `Conversation` под это зарезервировано.
- **HF-токен вводится вручную** на экране настройки и в приложении не сохраняется — при переустановке ввести заново.
- **Скачивание LLM — не на WorkManager.** Идёт в `viewModelScope` (через `ModelInstaller`); при сворачивании приложения может прерваться (докачка это переживёт). Зависимость `work-runtime-ktx` подключена, но менеджер загрузок на ней ещё не написан.
- **Иконка приложения** — заглушка. Заменить через Android Studio: правый клик на `res` → New → Image Asset.
- **Тестов почти нет.** Появился `SrsScheduleTest` (логика интервальных повторений), остальное — сгенерированные `ExampleUnitTest`/`ExampleInstrumentedTest`. Миграция БД `1 → 2` тестом не покрыта: `exportSchema = false`, а `MigrationTestHelper` требует instrumented-теста на устройстве.
- **Прогресс не синхронизируется и не бэкапится** — живёт только в локальной Room, при удалении приложения теряется.
- **Новые слова в повторение попадают строго по порядку курса** (от A1 к C1), а не по темам, которые пользователь реально открывал.

## Смена реализации движка

Всё завязано на `di/AppModule.kt`:

```kotlin
@Binds @Singleton
abstract fun bindSttEngine(impl: SherpaOnnxSttEngine): SttEngine   // ← или VoskSttEngine / AndroidSttEngine

@Binds @Singleton
abstract fun bindLlmEngine(impl: LiteRtLlmEngine): LlmEngine       // ← или StubTutorLlmEngine для разработки UI без модели
```

Чтобы разрабатывать UI без скачивания гигабайтной модели — верните `StubTutorLlmEngine` в `bindLlmEngine` (и, при желании, `AndroidSttEngine` в `bindSttEngine`), больше ничего менять не нужно.
