
# Specification: Voice Conversation

- **ID:** VC
- **Версия:** 1.0
- **Статус:** Draft — сверено с реализацией 2026-10-19, фактическое состояние и открытые вопросы — `specs/audit.md`

## 1. Цель

Определить ожидаемое поведение голосового диалога пользователя с языковым помощником, включая запись, распознавание, генерацию ответа, озвучивание и обработку ошибок.

Конкретные движки и технические реализации определяются по результатам аудита проекта.

## 2. Функциональные требования

### VC-001. Начало диалога

Когда пользователь запускает диалог, система должна проверить доступность необходимых компонентов и разрешений.

**Критерии приёмки:**
- При отсутствии разрешения на микрофон пользователь получает понятное объяснение.
- При недоступности обязательного компонента система не отображает состояние готовности.
- После устранения проблемы пользователь может повторить попытку.

### VC-002. Запись речи

Система должна сообщать пользователю, когда идёт запись, и завершать её по действию пользователя или предусмотренному механизмом записи правилу.

**Критерии приёмки:**
- Запись не начинается без необходимых разрешений.
- Ошибка записи не интерпретируется как успешный пустой ввод.
- При завершении записи ресурсы микрофона освобождаются.
- Поведение при отмене записи определено и проверяемо.

### VC-003. Распознавание речи

Система должна преобразовывать полученный аудиоввод в текст с использованием доступного STT-компонента.

**Критерии приёмки:**
- Пустой или нераспознанный ввод обрабатывается отдельно от корректного текста.
- Ошибка распознавания отображается пользователю.
- Пользователь может повторить попытку, если это допустимо.
- Результат отменённой операции не используется как актуальный ввод.

### VC-004. Генерация ответа

Система должна формировать ответ на основании пользовательского сообщения и согласованного контекста диалога.

**Критерии приёмки:**
- Во время генерации пользователь видит состояние обработки.
- При ошибке доступно понятное сообщение и, где возможно, повторная попытка.
- Ответ отменённой операции не заменяет более новый ответ.
- Порядок сообщений соответствует порядку диалога.

### VC-005. Озвучивание ответа

Система должна предоставлять озвучивание ответа, если эта функция поддерживается и включена.

**Критерии приёмки:**
- Текст ответа остаётся доступным при ошибке TTS.
- Воспроизведение можно остановить, если интерфейс предоставляет соответствующее действие.
- Новое воспроизведение не создаёт непредусмотренное наложение аудио.
- По завершении воспроизведения ресурсы освобождаются.

### VC-006. Отмена операций

Пользователь должен иметь возможность отменить текущую операцию в тех состояниях, где отмена предусмотрена интерфейсом.

**Критерии приёмки:**
- Отмена не запускает последующие этапы конвейера для отменённого ввода.
- Поздний результат отменённой операции не перезаписывает актуальное состояние.
- Повторная отмена безопасна.
- После отмены система переходит в определённое состояние.

### VC-007. Жизненный цикл приложения

Система должна корректно реагировать на закрытие экрана, уход приложения в фон и потерю аудиофокуса.

**Критерии приёмки:**
- Не остаётся незапланированной записи или воспроизведения после завершения соответствующего жизненного цикла.
- При возврате приложение не отображает устаревшую операцию как активную.
- Поведение в фоне явно определено.

### VC-008. Состояния диалога

Для процесса диалога должны быть определены состояния, эквивалентные следующим:

- готовность;
- запись;
- распознавание;
- генерация ответа;
- воспроизведение;
- отмена;
- ошибка.

**Критерии приёмки:**
- Для каждого состояния определены допустимые действия пользователя.
- Переходы между состояниями покрыты тестами.
- Ошибки не оставляют интерфейс в бесконечном состоянии загрузки.

### VC-009. Приватность

Обработка аудио и транскриптов должна соответствовать утверждённой политике приватности.

**Критерии приёмки:**
- Источники обработки данных документированы.
- Необязательные чувствительные данные не записываются в логи по умолчанию.
- Заявления о локальной обработке подтверждены аудитом реализации.

### VC-010. Тестируемость диалога

Основной процесс должен быть проверяем без физического микрофона и реальных тяжёлых ML-моделей, если архитектура позволяет использовать подмены.

**Критерии приёмки:**
- Успешный цикл диалога можно воспроизвести в автоматическом тесте.
- Проверены ошибки STT, LLM и TTS.
- Проверены отмена и получение запоздалого результата.

## 3. Нефункциональные требования

### VC-011. Производительность

Целевые задержки записи, распознавания, генерации и озвучивания необходимо согласовать после измерения текущей реализации.

До определения числовых значений нельзя заявлять соответствие конкретному SLA.

## 4. Открытые вопросы

- Какие STT-, LLM- и TTS-движки используются?
- Поддерживается ли потоковая генерация и потоковое озвучивание?
- Используется ли автоматическое определение конца речи?
- Что должно происходить при уходе приложения в фон?
- Какие данные диалога сохраняются и как долго?
- Должна ли обработка речи быть исключительно локальной?

## 5. Проверки

- Unit-тесты переходов состояний и отмены.
- Тесты ошибок каждого этапа.
- Интеграционный тест полного цикла с тестовыми адаптерами.
- UI-проверки разрешений и восстановления после ошибок.
- Проверки на устройстве для микрофона, аудиофокуса и lifecycle.
