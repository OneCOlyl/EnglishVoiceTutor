
# Specification: Learning Progress

- **ID:** LP
- **Версия:** 1.0
- **Статус:** Draft — сверено с реализацией 2026-10-19, фактическое состояние и открытые вопросы — `specs/audit.md`

## 1. Цель

Определить правила учебной сессии, сохранения результатов и отображения прогресса пользователя.

Конкретные учебные функции, алгоритмы оценки и персонализации должны быть подтверждены продуктовым замыслом и текущим кодом.

## 2. Функциональные требования

### LP-001. Учебная сессия

Система должна предоставлять пользователю предусмотренный приложением способ начать и завершить учебную сессию.

**Критерии приёмки:**
- Пользователь понимает, активна ли сессия.
- Отмена отличается от успешного завершения.
- Данные разных сессий не смешиваются.

### LP-002. Сохранение результата

Результат сессии должен сохраняться согласно определённым правилам завершения.

**Критерии приёмки:**
- Ошибка сохранения не сопровождается ложным подтверждением успеха.
- Отменённая сессия не считается успешно завершённой без явно определённого правила.
- Повторная обработка события не создаёт дубликаты там, где требуется идемпотентность.

### LP-003. История обучения

Если история обучения поддерживается, пользователь должен иметь доступ к сохранённым результатам.

**Критерии приёмки:**
- Для пустой истории предусмотрено понятное состояние.
- Результаты связаны с соответствующими сессиями.
- Политика удаления истории определена до реализации удаления.
- Ошибка чтения данных не интерпретируется как гарантированно пустая история.

### LP-004. Метрики прогресса

Каждая метрика должна иметь определённую формулу, источник данных и период расчёта.

**Критерии приёмки:**
- Одинаковые входные данные дают одинаковый результат.
- Пустые и некорректные данные обрабатываются явно.
- UI не отображает неподтверждённые проценты, баллы или оценки.
- Формулы доступны для проверки и покрыты тестами.

### LP-005. Языковая обратная связь

Если приложение оценивает речь или исправляет ошибки, оно должно различать исправления и альтернативные варианты выражения.

**Критерии приёмки:**
- Пользователь понимает, что именно исправлено и почему.
- Альтернативная формулировка не выдаётся за единственно правильную без основания.
- Недоступность анализа не приводит к ложному сообщению об успешной проверке.

### LP-006. Персональные рекомендации

Если рекомендации основаны на истории обучения, правила их выбора должны быть определены и проверяемы.

**Критерии приёмки:**
- Для рекомендации существует объяснимое правило выбора.
- При отсутствии истории используется определённое базовое поведение.
- Алгоритм проверяется на фиксированном наборе примеров.
- Рекомендации не выдаются за объективную оценку уровня языка без согласованного метода оценки.

## 3. Данные и приватность

- Хранить только данные, необходимые для предусмотренных учебных сценариев.
- Определить, сохраняются ли аудио, транскрипты, исправления и история ответов.
- Определить правила удаления пользовательских данных.
- Сопровождать изменения схемы хранения миграциями и тестами.
- Документировать, какие данные передаются внешним компонентам, если такие компоненты используются.

## 4. Открытые вопросы

- Какие учебные сценарии входят в MVP?
- Как определяется корректность ответа?
- Как оценивается произношение, если такая функция предусмотрена?
- Используется ли интервальное повторение слов?
- Какие показатели прогресса действительно нужны пользователю?
- Как долго хранится история обучения?
- Должны ли данные экспортироваться или удаляться по запросу пользователя?

## 5. Проверки

- Unit-тесты вычисления метрик.
- Тесты правил завершения учебной сессии.
- Тесты сохранения, чтения и миграций.
- UI-тесты пустой истории и ошибок сохранения.
- Регрессионные тесты на фиксированных учебных данных.
